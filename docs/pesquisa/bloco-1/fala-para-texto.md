# Local speech-to-text for Brazilian Portuguese with word-level timestamps, running in the Electron 45 editor on Windows 10/11 x64 (CPU-only must work, GPU optional)

## Summary
Among local models that fit a laptop, OpenAI Whisper large-v3-turbo has the best pt-BR text accuracy. On FLEURS-pt (Brazilian, Q8_0) it scores 4.17% WER (Q5_K_M: 4.14%), against 4.96% for NVIDIA Parakeet-TDT-0.6B-v3, 5.07% for whisper-medium and 7.65% for whisper-small. On a small real-world informal pt-BR set (15 clips) turbo scored 6.7% WER and Parakeet v3 11.6%. Speed is the trade-off. On a Ryzen 7 4750U CPU, turbo runs at about 1.4x real time (about 43 s per audio minute) and Parakeet at about 13.7x (about 4-5 s). On 4-core, 15 W 10th-gen i5 laptops, turbo can be slower than real time. Timing precision also differs: in an English benchmark, Whisper's word times are off by about 150 ms on average and start early, Parakeet's by about 79 ms, and WhisperX-style CTC alignment by about 37-47 ms. Recommended primary: whisper.cpp v1.9.5. Use the official prebuilt whisper-cli.exe (Windows x64 assets on build tag b5454) and spawn it from the main process, the same way the app runs ffmpeg. Model: ggml-large-v3-turbo-q5_0 (574 MB), with language forced to pt, Silero VAD v6.2.0 pre-segmentation done by the app, and DTW token timestamps (-dtw large.v3.turbo -nfa -ojf). Reading the source and the binaries turned up pitfalls that the plan must handle: (1) DTW is silently disabled unless flash attention is turned off; (2) token and DTW times in the JSON are not remapped when --vad is used, and -p>1 also corrupts token offsets; (3) whisper-cli takes ANSI argv with no UTF-8 manifest, so non-ASCII paths fail, which matters for accented Brazilian usernames; (4) the official EXE/DLLs need the VC++ runtime DLLs, which the zip does not include. Recommended fallback: sherpa-onnx-node 2.0.1 (prebuilt N-API for win-x64, Apache-2.0, statically linked) with sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8 (about 640 MB), run in an Electron utilityProcess. It is about 10x faster, gives native token start, duration and confidence, and hallucinates much less. On the other hand it is less accurate on informal pt-BR, cannot be forced to Portuguese, and was trained on European Portuguese. Rejected: the Node whisper addons (none expose DTW token times, and several are stale or compile at install), transformers.js v4 (slow on CPU, WebGPU fp16 bugs with turbo, huge downloads), faster-whisper standalone builds (no license, PyInstaller), and Vosk pt (27-69% WER). Forced alignment is not needed for v1: refine word edges from the VAD and energy curves before any audio cut, and keep wav2vec2-xlsr-53-portuguese (Apache-2.0) as a later upgrade. On non-speech audio, Silero VAD alone cut hallucination WER from 104.8% to 8.0%, and adding de-looping and a phrase filter brought it to 6.5%. Captions should come in two presets: 'Shorts' with 1-3 words, and 'Clássico' following Netflix pt-BR (42 chars per line, 2 lines, at most 17 cps, 5/6 s to 7 s per caption). Correct words in a transcript panel that highlights low-confidence words.

## Choice
PRIMARY ('Preciso'): whisper.cpp v1.9.5. Use the official prebuilt Windows x64 CPU build from release tag b5454 (whisper-bin-x64.zip) and spawn whisper-cli.exe from the main process. Model: Whisper large-v3-turbo q5_0 (ggml-large-v3-turbo-q5_0.bin, 574 MB), forced to Portuguese (-l pt). The app does its own Silero VAD v6.2.0 pre-segmentation, and word times come from DTW token timestamps (-dtw large.v3.turbo -nfa -ojf). FALLBACK ('Rápido'): sherpa-onnx-node 2.0.1 running NVIDIA Parakeet-TDT-0.6B-v3 int8 in an Electron utilityProcess.

## Why
Users notice wrong words before they notice timing, and Whisper large-v3-turbo is the most accurate laptop-sized local model on pt-BR (FLEURS-pt 4.17% vs 4.96% for Parakeet v3; informal pt-BR 6.7% vs 11.6%). It can be pinned to Portuguese, biased with a glossary prompt, and writes Brazilian spelling. Parakeet cannot be forced to a language and was trained on European Portuguese. whisper.cpp is MIT-licensed, very active (v1.9.5, Oct 2026) and ships official Windows x64 binaries with runtime CPU-variant dispatch. Its CLI is the only off-the-shelf way to get DTW token timestamps, because the Node addons don't expose them. Spawning it copies the editor's existing ffmpeg pattern: crash isolation, cancel by kill, no asar/ABI/rebuild concerns (npmRebuild:false stays). The primary's weak points have specific mitigations. Slow CPUs: first-use calibration, plus the fallback. Hallucinations: VAD, filters and de-looping. About 150 ms timing error: waveform edge refinement before any audio cut. Antivirus/runtime issues: signing, app-local VC++ DLLs, and the fallback. Parakeet via sherpa-onnx is the right fallback because it fails differently: a different runtime (onnxruntime), statically linked prebuilt N-API binaries that work in Electron, about 10x faster on CPU, better native timing (79 ms MAE), confidence scores and near-zero hallucination.

Keep only Release/{whisper-cli.exe, whisper-vad-speech-segments.exe, whisper.dll, ggml.dll, ggml-base.dll, ggml-cpu-{x64,sse42,sandybridge,haswell,skylakex,icelake,cascadelake,cannonlake,alderlake}.dll} (14 files, 12.0 MB) and put them in vendor/whisper/. These import msvcp140.dll, vcruntime140.dll and vcruntime140_1.dll, which the zip does not contain. Copy the x64 VC++ 2015-2022 runtime DLLs app-locally next to whisper-cli.exe (from the Visual Studio redist Microsoft.VC14x.CRT folder; app-local deployment is permitted), or build the same tag yourself with -DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded.
2) electron-builder: add extraResources [{from:'vendor/whisper', to:'stt/whisper'}]. Resolve at runtime as path.join(process.resourcesPath,'stt','whisper','whisper-cli.exe'). Extend scripts/after-pack.cjs to assert these files exist, the same way it checks ffmpeg. When code signing is added, also sign .exe/.dll/.node (win.signExts).
3) Fallback dependency: "sherpa-onnx-node": "2.0.1" (exact pin; it pulls the optional "sherpa-onnx-win-x64": "2.0.1", about 23 MB, static CRT). Add 'node_modules/sherpa-onnx-node/**' and 'node_modules/sherpa-onnx-win-x64/**' to asarUnpack. N-API, so npmRebuild:false is fine.

B. MODELS (downloaded on first use into <userData>/stt/models; HTTP Range resume, temp file then rename, SHA-256 pinned at build time, mirrored on your own GitHub release as a backup)
- Preciso: ggml-large-v3-turbo-q5_0.bin (574 MB) from huggingface.co/ggerganov/whisper.cpp, plus ggml-silero-v6.2.0.bin (about 0.86 MB) from huggingface.co/ggml-org/whisper-vad. Before freezing the default, A/B the speed of q5_0 vs q8_0 (874 MB) vs a self-made q4_0 (whisper-quantize.exe) on 3 reference laptops. Handy measured Q5_K_M as accurate as Q8_0 for pt.
- Rápido: sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8 (encoder.int8.onnx 622 MB, decoder.int8.onnx 12 MB, joiner.int8.onnx 6.1 MB, tokens.txt) from k2-fsa/sherpa-onnx releases tag 'asr-models'. It ships as tar.bz2, so re-host the files unpacked. Also needs silero_vad.onnx.
- 'Sobre > Licenças': whisper.cpp MIT, Whisper MIT, Silero VAD MIT, sherpa-onnx Apache-2.0, onnxruntime MIT, Parakeet CC-BY-4.0 (credit NVIDIA).

C. PRIMARY PIPELINE (main process; one job per 'Gerar legendas')
1) Timeline range [t0,t1] to source spans. For each video clip overlapping the range, with !muted and volume>0: srcStart = clip.in + max(0, t0 - clip.start), srcEnd = clip.in + min(clip.duration, t1 - clip.start).
2) Job dir: <userData>/stt/jobs/<id>/. Spawn every tool with cwd = job dir and only relative ASCII arguments (e.g. -m ..\..\models\ggml-large-v3-turbo-q5_0.bin). whisper-cli has no UTF-8 manifest and reads ANSI argv, so absolute paths such as C:\Users\João\... fail.
3) Extract, using the same input-seek convention as src/core/export.ts: ffmpeg -hide_banner -nostdin -loglevel error -y -ss {srcStart} -t {dur} -i <media> -map 0:a:0 -vn -sn -dn -ac 1 -ar 16000 -c:a pcm_s16le -map_metadata -1 -fflags +bitexact -f wav audio.wav
4) VAD: whisper-vad-speech-segments.exe -vm ..\..\models\ggml-silero-v6.2.0.bin -f audio.wav -t 4 -vt 0.5 -vspd 250 -vsd 300 -vp 200 -vmsd 25. Parse lines of the form 'Speech segment i: start = X, end = Y' (centiseconds). Keep the segments; breath detection reuses them.
5) In Node, write speech.wav: the speech segments joined with 0.4 s of digital silence between them, plus a mapping table [{vStart,vEnd,oStart,oEnd}]. Process in batches of at most about 5 min of speech per whisper run, so results arrive progressively and a cancel loses little.
6) Transcribe: whisper-cli.exe -m ..\..\models\ggml-large-v3-turbo-q5_0.bin -f speech.wav -l pt -t {physical cores, max 8} -nfa -dtw large.v3.turbo -sns -mc 64 --prompt "{one pt-BR sentence with punctuation + glossary of names/brands}" --carry-initial-prompt -ojf -of out -np -pp
Rules: -nfa is mandatory (flash attention is on by default and silently disables DTW). Never use --vad here (token and DTW times stay in the VAD timeline). Never use -p>1 (token offsets bug). Note that -mc 0 would drop the glossary prompt too. Progress comes from 'progress = N%' on stderr; cancel by killing the process.
7) Words from out.json transcription[].tokens[] ({text, offsets{from,to}, id, p, t_dtw}):
- Drop special tokens ('[_...]').
- A token starting with a space opens a new word; punctuation-only tokens attach to the previous word.
- start = t_dtw*10 ms (if t_dtw = -1, use offsets.from).
- end = min(start of next word, offsets.to of the last token), with at least 60 ms per word.
- conf = min token p.
- Map times back through the table; a time inside an inserted gap snaps to the nearest segment edge.
8) Clean:
- Drop words outside VAD speech.
- De-loop: collapse 3 or more consecutive repeats of the same 1-6-word sequence.
- Apply a pt-BR bag-of-hallucinations filter to short, low-p segments ('Legendas pela comunidade Amara.org', 'Obrigado.', 'Obrigado por assistir', 'Inscreva-se no canal', '♪'). Grow the list by running the model over music and room tone.
- Refine each word edge within ±120 ms to the nearest Silero-probability or short-time-energy transition. This is mandatory before any audio cut.
- Measure on the pt-BR test set whether a constant start-bias correction helps.
9) Cache the transcript (source-time words) in <userData>/stt/cache/<sha1(path,size,mtime,span,engine,model,paramsVersion)>.json. Trims and re-generation reuse it.
10) Timeline time = clip.start + (src - clip.in).

D. FALLBACK PIPELINE: utilityProcess.fork('dist/main/stt-worker.cjs', [], {serviceName:'Diretor STT', stdio:'pipe'})
The worker runs require('sherpa-onnx-node') with:
- new Vad({sileroVad:{model:'silero_vad.onnx', threshold:0.5, minSilenceDuration:0.3, minSpeechDuration:0.25, maxSpeechDuration:20, windowSize:512}, sampleRate:16000}, 60)
- new OfflineRecognizer({featConfig:{sampleRate:16000, featureDim:80}, modelConfig:{transducer:{encoder,decoder,joiner}, tokens, numThreads:N, provider:'cpu', modelType:'nemo_transducer'}, decodingMethod:'greedy_search'})
For each segment: call vad.front(false) (enableExternalBuffer=false is mandatory in Electron 21+), then stream.acceptWaveform({samples, sampleRate:16000}), then await rec.decodeAsync(stream). The result has {tokens, timestamps, durations, ys_log_probs}. A word runs from a '▁' token to the next one: start = segStart + timestamps[i], end = segStart + timestamps[j] + durations[j], conf = exp(mean of the log-probs). Then apply the same steps C8-C10.

E. ENGINE CHOICE
On first use, transcribe a bundled 20 s pt-BR clip with turbo and measure RTF.
- RTF ≤ 0.8: default to Preciso.
- 0.8 < RTF ≤ 2: Preciso for ranges of 2 min or less; otherwise ask.
- RTF > 2, or primary failure (exe missing or quarantined, crash, non-zero exit): Rápido, with a pt-BR message.
Always show an ETA and a Cancel button.

F. CAPTION CHUNKER (pure TypeScript in src/core, unit-tested)
Presets:
- 'Shorts': 1-3 words, at most 16-18 chars, 1 line (2 at most), 0.3-1.5 s on screen, hold at most 0.25 s into silence.
- 'Clássico' (Netflix pt-BR): at most 42 chars per line and 2 lines, at most 17 cps, 0.833-7 s, minimum gap 2 frames, hold at most 0.5 s.
Segmentation: dynamic programming over the word list.
- Hard limits: line overflow and maximum duration.
- Soft costs: cps above the limit, too-short captions, line imbalance.
- Break bonus: after . ? ! … (strong) and after , ; : (medium).
- Penalty for ending a caption or line on: articles, prepositions and contractions (o a os as um uma de do da dos das em no na nos nas por pelo pela para pra com sem ao à); conjunctions (e ou mas que se porque quando como); clitics (me te se lhe nos); 'não'; auxiliaries (vou vai vamos tá está estou foi tem tenho); or between consecutive capitalized names.
Timing: start = first word start (no earlier than previous end + gap); end = last word end + hold; extend toward the minimum duration only into silence; snap to the project fps.

G. DATA MODEL (additive, backward-compatible)
- CaptionClip.words?: {t:string; s:number; e:number; c?:number}[] (seconds relative to clip start).
- TextStyle.strokeColor?: string; TextStyle.strokeWidth?: number (em, e.g. 0.12); TextStyle.highlightColor?: string.
- CaptionClip.source?: {transcriptKey:string}.
- In renderFrame: strokeText (lineJoin 'round') then fillText, for the yellow-with-black-outline look.

H. UX (same screen)

  - Click a word to seek and play it with 0.3 s pre-roll; double-click or Enter edits it inline; Tab jumps to the next doubtful word.
  - Typing several words into one word's slot splits its time by character count; deleting a word merges its time into its neighbours.
  - Enter/Backspace split or merge captions.
  - 'Substituir em tudo' (replace everywhere).
  - 'Dicionário do projeto': names and brands are fed to --prompt and applied as post-replacements.
  - 'Refazer trecho' re-runs a passage with Preciso.

I. MCP
- New tool generate_captions(range, mode, preset) that returns a proposal.
- get_context (economy mode) includes caption text plus a list of low-confidence words, without per-word timings, to stay under 6 KB.

J. QA BEFORE LOCKING DEFAULTS

## Risks
- CPU speed: on 4-core/15 W laptops turbo can be 1-3x slower than real time, so calibration, the Rápido fallback and (later) Vulkan are required
- Whisper hallucinations and loops on music, silence or laughter: VAD plus filters reduce them a lot but not to zero (residual 6.5% WER on non-speech in the BoH paper)
- Timing: Whisper word starts are about 150 ms early on average (English benchmark); DTW gives one time per token, so ends are estimated; refine from the waveform before any cut; karaoke-grade sync may later need forced alignment
- whisper-cli takes ANSI argv with no UTF-8 manifest, so absolute non-ASCII paths fail: use cwd plus relative ASCII paths, or rebuild with a UTF-8 manifest
- Official whisper.cpp binaries need msvcp140, vcruntime140 and vcruntime140_1, which are not in the zip; clean PCs fail with 'VCRUNTIME140_1.dll not found' unless shipped app-locally or rebuilt with static CRT
- Upstream CLI quirks may change: --vad and -p>1 token-time bugs (PRs #3764/#3766 open), flags renamed; pin to b5454, parse JSON defensively, re-test on every bump
- Antivirus/SmartScreen: unsigned exe/dll can be quarantined (already seen with ffmpeg.exe); sign everything and add a missing-binary repair path
- Release assets are attached to bNNNN pre-release tags; vendor at build time with SHA-256, never download executables at runtime
- Parakeet fallback: European-Portuguese spellings, no language forcing (wrong-language flips), weaker on informal pt-BR and numbers; CC-BY-4.0 attribution
- sherpa-onnx in Electron: enableExternalBuffer=false required; onnxruntime.dll version clash with another copy on the system; must be asarUnpacked; run in a utilityProcess so a native crash doesn't kill the editor
- Downloads of 574-640 MB on slow or metered Brazilian connections: need resume, checksum, mirror and disk-space checks
- RAM and CPU contention with preview/video decoding on 8 GB laptops; consider pausing preview or reducing threads during a job
- Thin public pt-BR spontaneous-speech evidence (tech4humans has n=15; FLEURS is read speech; FA-Bench timing is English only): validate in-house
- Whisper output is non-verbatim (drops hesitations and fillers), which matters for the breath/filler-cut features; detect those from audio, not from text
- Benchmark dates are partly unstated (Handy) and models move fast; re-check parakeet-ultra / Qwen3-ASR / transcribe.cpp in 2027

## Fallback
sherpa-onnx-node@2.0.1 with sherpa-onnx-win-x64@2.0.1 (prebuilt N-API, Apache-2.0, about 23 MB, static CRT) running NVIDIA Parakeet-TDT-0.6B-v3 int8 (sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8: encoder 622 MB, decoder 12 MB, joiner 6.1 MB) plus silero_vad.onnx, inside an Electron utilityProcess. Labelled 'Rápido' in the UI. It is selected automatically when calibration shows the primary at RTF > 2, for long ranges on slow machines, or when whisper-cli is missing, quarantined or crashing. It gives native token start, duration and log-prob confidence and runs at about 13.7x real time on a 4750U CPU, but is less accurate on informal pt-BR and cannot be forced to Portuguese. Last-resort fallback inside the primary engine: whisper-cli with ggml-small-q8_0.bin (264 MB; FLEURS-pt 7.65%; about 5.9x real time on a 4750U).

## User-facing constraints
- First use needs a one-time download of about 575 MB for 'Preciso' (plus about 640 MB if 'Rápido' is enabled) and about 1.5 GB of free disk. After that everything works offline and the video never leaves the PC.
- Processing time without a graphics card: 'Preciso' takes roughly 40-60 s per minute of speech on a recent 8-core laptop, but 1-3 minutes per minute on older or low-power 4-core laptops. 'Rápido' takes about 5-10 s per minute. Silent parts are skipped, so pauses cost almost nothing.
- While transcribing, the app uses about 1-1.5 GB of RAM and most of the CPU. On 8 GB laptops, close other heavy apps; the preview may stutter until the job finishes.
- Expect about 4-7 wrong words per 100 with 'Preciso' on clear Brazilian speech. Expect more with background music, noise, slang, names and brands. Adding names to the project dictionary helps.
- 'Rápido' makes noticeably more mistakes on informal speech. It may sometimes use Portugal-style spellings (e.g. 'facto', 'económico') or write a few words in another language.
- Captions come out as clean text: hesitations like 'é...' or 'hum' are usually not written, and numbers may appear as digits.
- Words are synced to about a tenth of a second. That is fine for 1-3-word captions; for audio cuts the app fine-tunes the edges from the sound wave.
- On silence or music the engine can invent phrases (e.g. 'Legendas pela comunidade Amara.org', 'Obrigado.'). The app filters known ones, but captions should be reviewed.
- Antivirus software may block or remove the speech engine. If that happens, the app explains how to restore it or reinstall. A graphics card can speed things up in a later version but is never required.

## Product questions
- Default caption look: 1-3 words at a time (CapCut/Reels style) for vertical videos and 2-line subtitles for horizontal ones, or a single style everywhere?
- Is a one-time ~575 MB download on first use acceptable, or should the model be bundled in the installer (installer then grows by ~600 MB)? Should the 'Rápido' engine (+~640 MB) be offered at all?
- On slow laptops, should the app automatically switch to the faster but less accurate 'Rápido' mode, or always prefer accuracy and let the user wait (with an ETA)?
- Should generated captions arrive as a draft to accept, adjust or discard (like AI edits), or be inserted directly with undo?
- May transcript text be sent to the AI assistant (Claude Code/Codex on the user's subscription) to suggest corrections and punctuation? The media stays local, but the text would go to the AI provider.
- Is word-by-word highlighting (karaoke) needed in v1? If it must be frame-accurate, a later forced-alignment step (an extra ~0.3-1.3 GB model) may be needed.
- Caption text rules: numbers as digits or words; keep or remove fillers ('né', 'tipo') and profanity; maximum words per caption?
- Will the app be sold or distributed commercially? This decides which model licenses are acceptable (CC-BY needs on-screen attribution; non-commercial models such as MMS are excluded).


## Checagem independente das afirmações

Uma segunda pesquisa tentou refutar cada afirmação (22 no total: confirmed 19, partly 3). Abaixo, só as que foram corrigidas ou que trazem uma ressalva. Onde a correção conflita com o texto acima, vale a correção.

- **stt-2** (partly — **muda a recomendação**). Afirmação: whisper.cpp Windows EXE/DLLs import msvcp140, vcruntime140, vcruntime140_1 (not in zip); sherpa-onnx-win-x64 2.0.1 binaries do not import the VC++ runtime.
  - Correção: The official b5454 binaries need FOUR MSVC runtime DLLs: msvcp140.dll, vcruntime140.dll, vcruntime140_1.dll AND vcomp140.dll (the OpenMP runtime, imported by ggml-base.dll and every ggml-cpu-*.dll). whisper.dll and ggml.dll load ggml-base.dll at load time, so without vcomp140.dll whisper-cli.exe does not start at all on a clean PC. The binaries are linked with MSVC 14.51 (VS 2026), so the copies placed next to the exe must come from a v14 redist at version 14.51 or newer, taken from the CRT and the OpenMP redist folders of a VS 2026 install. VC++ 2015-2022 DLLs (14.44 or older) do not qualify. The alternative of a self-built /MT static-CRT build must also set -DGGML_OPENMP=OFF, or keep shipping vcomp140.dll. The same applies to the Phase-2 Vulkan build line. The sherpa-onnx part of the claim is correct.
  - Evidência: Local objdump -p on the extracted b5454 files. ggml-base.dll imports KERNEL32, VCOMP140.DLL, MSVCP140, VCRUNTIME140, VCRUNTIME140_1 and api-ms-win-crt-*. All nine ggml-cpu-*.dll import VCOMP140.DLL, MSVCP140, VCRUNTIME140 and VCRUNTIME140_1 (plus ADVAPI32). whisper-cli.exe, whisper.dll and ggml.dll import MSVCP140, VCRUNTIME140 and VCRUNTIME140_1. The zip contains no runtime DLLs. The PE headers of whisper-cli.exe, whisper.dll and ggml-base.dll show MajorLinkerVersion 14 and MinorLinkerVersion 51, i.e. the MSVC 14.51 toolset (VS 2026). Microsoft: 'The version of the redistributable installed on the machine must be the same or higher than the version of the MSVC Build Tools used to create your application' (https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist); vcomp[version].dll is the redistributable 'OpenMP Library for native code', and local deployment is allowed but not recommended (https://learn.microsoft.com/en-us/cpp/windows/determining-which-dlls-to-redistribute?view=msvc-170). Sherpa side, from npm sherpa-onnx-win-x64-2.0.1.tgz: sherpa-onnx.node imports sherpa-onnx-c-api.dll and KERNEL32 (node.exe is delay-loaded); sherpa-onnx-c-api.dll imports onnxruntime.dll and KERNEL32; onnxruntime.dll imports KERNEL32, ADVAPI32, api-ms-win-core-path, dbghelp, SETUPAPI and dxgi. No VC++ runtime.
- **stt-3** (confirmed). Afirmação: whisper-cli.exe has no activeCodePage=UTF-8 manifest, parses narrow argv, whisper_init_from_file converts the model path UTF-8 to UTF-16 under MSVC; absolute non-ASCII paths expected to fail; relative ASCII paths with parent-set cwd avoid it.
  - Correção: The conclusion is right. One detail: from_bytes() throws std::range_error on CP1252 bytes such as 0xE3 ('ã'), so expect an abort or crash, not a clean 'failed to open'. The same ANSI argv also corrupts any non-ASCII --prompt text (see other_problems).

### Outros problemas que a checagem encontrou

- Step A1/K (clean PC breaks): shipping only msvcp140, vcruntime140 and vcruntime140_1 is not enough. vcomp140.dll (OpenMP, imported by ggml-base.dll and every ggml-cpu-*.dll) is also needed, otherwise whisper-cli.exe fails to start. The DLLs must come from a v14 redist at 14.51 or newer (the binaries are linked with MSVC 14.51, VS 2026), not 'VC++ 2015-2022'. Both the /MT rebuild option and the Phase-2 Vulkan build need -DGGML_OPENMP=OFF, or must still ship vcomp140.dll. The QA 'clean VM' test should check for the VCOMP140.DLL error specifically.
- Step C6 / 'Dicionário do projeto' cannot work as written. whisper-cli gets argv in the ANSI code page (CP1252 on pt-BR Windows), so a --prompt with accented words ('João', 'ação', 'Ribeirão') reaches the tokenizer as invalid UTF-8 bytes and the glossary is corrupted. Fix: put all arguments in a UTF-8 response file and run 'whisper-cli.exe @args.txt'. That is supported only when it is the sole argument (b5454 cli.cpp lines 983-1006). The file needs one argument per line with LF endings, because std::getline keeps a trailing '\r' with CRLF, which breaks flags. Paths inside the file stay relative ASCII, because -f and -of are opened with ANSI fopen.
- Step C6: with -mc 64 and --carry-initial-prompt, max_prompt_ctx = min(64, 448/2) = 64. The initial prompt is capped at 63 tokens: only the LAST 63 are kept, with a warning, so the style sentence is dropped first. That leaves 0 tokens of rolling context (whisper.cpp b5454 lines 7101-7130 and 7285-7300). The sentence plus the glossary must fit in about 63 Whisper tokens; give the glossary its own budget and validate it.
- Speed and ETA assumptions: whisper-cli defaults to beam search, because beam_size defaults to 5 and cli.cpp picks BEAM_SEARCH when beam_size > 1. DTW also forces -nfa (flash attention off). The quoted speeds (Handy 1.4x on the 4750U, voiceping) were not measured with -nfa -dtw and beam 5, so the '40-60 s per minute' estimate and the calibration thresholds are unverified. Benchmark -bs 1 -bo 1 against the default for both speed and WER.
- Step E calibration: a 20 s clip still costs a full 30 s encoder window, and a one-off run includes loading the 574 MB model. The measured RTF is therefore overstated by roughly 1.5x or more, which pushes machines to 'Rápido' unnecessarily. Use a clip of 30 s or more (one or two full windows), exclude load time, or calibrate on the first real batch.
- Step D word assembly is wrong for sherpa-onnx. SymbolTable::operator[] replaces the leading '▁' with a space (sherpa-onnx v2.0.1 symbol-table.cc lines 191-199), so result tokens never start with '▁' and every segment becomes one 'word'. Split on tokens that begin with ' '. Also: TDT durations can be 0 frames, times sit on an 80 ms grid, each segment needs its own OfflineStream, and readWave(path, false) is required in Electron if it is used.
- Build plumbing the rec omits. scripts/build-main.mjs bundles with external: ['electron','ffmpeg-static'] only, and sherpa-onnx-node's addon-static-import.js statically requires '../sherpa-onnx-win-x64/sherpa-onnx.node'. The worker bundle must therefore mark 'sherpa-onnx-node' as external, or the bundle breaks or cannot find the addon. utilityProcess.fork needs an absolute path such as path.join(__dirname,'stt-worker.cjs'); the relative 'dist/main/stt-worker.cjs' breaks once packaged.
- Step C3: '-map 0:a:0' aborts on a clip with no audio stream. Verified locally with ffmpeg 7.0.2: exit 234, "Stream map '0:a:0' matches no streams". Probe for an audio stream first, or use '-map 0:a:0?' and skip clips without audio. Otherwise the command worked: a 7.5 s, 16 kHz, mono, s16 WAV from bench/long60.m4a.
- Missed candidate: Parakeet Ultra (moondream post-train of parakeet-tdt-0.6b-v3, CC-BY-4.0, listed on OpenRouter as 2026-11-03). On the same Handy page it scores 4.16% FLEURS-pt WER (turbo 4.17%) at 13.3x real time on the 4750U CPU, about the speed of v3; Moondream's own figure is 3.96% vs 4.65% for v3. It has the same architecture and tokenizer as v3, so a sherpa-onnx export would be a model swap for 'Rápido' and could shift the Preciso/Rápido trade-off. It is published in transformers format and no sherpa-onnx export was found. It keeps the EU-pt and no-language-forcing caveats. Put it in the J bake-off now, not in 2027. Sources: https://models.handy.computer/languages/pt , https://huggingface.co/DictionLabs/parakeet-ultra , https://openrouter.ai/moondream/parakeet-ultra
- Model choice: the 'no measurable loss' evidence is for Q5_K_M, but the rec ships q5_0, an older and different scheme. whisper-quantize at b5454 supports q5_k (examples/common-ggml.cpp). The A/B should measure WER as well as speed for q5_0 against q5_k and q8_0.
- whisper-server.exe in the same zip also supports -dtw and -nfa and returns per-word t_dtw in verbose_json (b5454 examples/server/server.cpp lines 1113-1146). It keeps the model loaded across batches and takes the prompt as UTF-8 in an HTTP form, which avoids both the argv encoding problem and per-batch model reloads (at the cost of a localhost port). So 'the CLI is the only off-the-shelf way to get DTW' is inaccurate.
- Parsing risk: the b5454 README for vad-speech-segments shows second-like values ('start = 0.29'), but the b5454 code prints centiseconds (usage text: 'Output timestamps are in centiseconds'; samples_to_cs). The b5454 whisper-cli README is also stale ('-fa [false]', no -nfa or --carry-initial-prompt). Pin the expected format with a CI parse test against the vendored binary instead of the README.
- Rápido glossary: NeMo transducers in sherpa-onnx support modified_beam_search with per-stream hotwords (CHANGELOG #3077; createStream(hotwords) in non-streaming-asr.js). The 'Dicionário do projeto' can bias the fallback too, not only Whisper's --prompt.
- Evidence framing in the rec: the hallucination paper's 104.8 -> 8.0 -> 6.5% WERs are on short, probably English, speech clips padded with noise (large-v3), not 'on non-speech audio'. The tech4humans Whisper rows were API runs. User copy saying words are 'synced to about a tenth of a second' is optimistic: FA-Bench measures Whisper at 148 ms MAE (English), and only DTW's grid is 20 ms.
- 'Clássico' preset: 17 cps is Netflix's limit for interlingual subtitles. For same-language captions the SDH limit of 20 cps for adults is the closer precedent. 17 is conservative and still valid, but it splits captions more than necessary.
